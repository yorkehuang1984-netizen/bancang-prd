板仓 PedalBoard — 产品需求文档（PRD）

版本：v1.0 | 日期：2026-08-10 | 作者：交互式 PRD（原型驱动）

状态：MVP 定义阶段 | 定位：效果器垂直社区

1. 产品概述

1.1 产品定位

板仓（PedalBoard）是一个效果器垂直社区平台。为效果器爱好者、商家和内容创作者提供专属的信息检索、讨论交流和设备展示空间。

1.2 一句话描述

效果器爱好者的专属讨论空间 — 从发现设备到交流心得，一站式解决。

1.3 核心价值主张

用户痛点 板仓方案
效果器讨论分散在微信群、视频评论区、综合论坛 垂直聚合，按效果器型号归拢所有讨论
微信聊天记录不可检索，信息快速沉没 每条帖子永久存在、可被搜索、按效果器归类
想了解某款效果器，需要跨平台搜索多个来源 一个效果器一个页面：简介 + 用户评测 + 相关帖子
买效果器前没有集中的口碑参考 排行榜 + 真实用户评价 + 未来接入二手市场价格

1.4 产品愿景

  • 短期（MVP）：为效果器爱好者提供可检索的垂直讨论空间，建立首批内容
  • 中期（V2）：接入效果器数据库 + 二手交易信息 + KOL 内容生态
  • 长期（V3）：成为华语效果器社区的基础设施 — 购买决策、二手估价、设备展示、教程资源

2. 用户分析

2.1 目标用户分层

用户类型 描述 核心需求 对平台的价值
**普通爱好者** 拥有 3-15 块效果器，常逛闲鱼/B站/微信群 了解效果器口碑、对比选择、展示自己的板子 内容消费 + UGC 生产 + 社区氛围
**深度玩家** 拥有大量设备，有改机/DIY 经验，积极参与讨论 深度技术交流、分享改机经验、建立个人声望 高质量内容生产 + 社区权威
**内容创作者（KOL）** 在 B站/小红书/YouTube 发布效果器相关内容 内容分发 + 粉丝沉淀 + 变现渠道 流量引入 + 内容供给
**官方商家** 品牌直营或授权经销商 品牌曝光 + 新品宣发 + 用户触达 商业变现 + 官方信息权威来源
**零售琴行** 线下或线上琴行 引流获客 + 库存曝光 商业变现 + 本地化服务

2.2 用户角色重合原则

同一用户可同时拥有多重角色。角色不由平台预先分配；由用户行为和社区认可自然形成：

  • KOL 身份：由内容质量决定（获赞/收藏/关注数达到阈值），非平台主动授予
  • 商家认证：需提交品牌授权证明或营业执照，平台审核后标识为「认证商家」
  • 平台冷启动期：可主动邀请其他平台上的效果器博主入驻，但不授予特殊身份标识；其身份同样由后续内容表现决定

2.3 典型使用场景

场景 用户路径
想买一块延迟效果器，不知道选哪个 打开板仓 → 发现页 → 延迟排行榜 → 浏览排名 → 点开 DD-8 详情看评测和帖子
刚买了一块新单块，想晒出来 首页 → 点 + → 发布帖子 → 上传图片 + 写体验 → 发布成功
设备出了问题，想求助 搜索效果器名称 → 找到相关帖子 → 在评论中提问
想卖掉闲置设备 未来（V2）：效果器详情页查看二手市场参考价 → 引流至闲鱼

3. 竞品分析

平台 优势 对效果器用户的主要缺陷
**微信群/QQ 群** 即时交流、高活跃度 信息不可检索、不可沉淀、无法按效果器归类
**吉他中国论坛** 老牌社区、帖子可检索 综合音乐论坛，效果器只是子版块；UI 老旧；移动端体验差
**B站/小红书** 视频/UGC 生态成熟、流量大 泛内容平台，效果器内容被算法稀释；评论区不适合深度讨论
**闲鱼** 交易数据真实 非社区，不适合做内容沉淀；交易完成后讨论即结束
**Equipboard** 效果器数据库 + 艺术家设备展示 英文社区，华语用户参与度低；偏展示而非讨论
**The Gear Page** 全球最大的设备讨论社区 全英文；以欧美设备文化为主；需要科学上网

板仓的差异化空间：华语效果器用户缺少一个移动优先、可检索、设备导向、中文原生的垂直讨论空间。

7. 功能规格说明

7.1 发现页 — 分类卡片

属性 规格
布局 2 列 × 3 行网格（CSS Grid）
每个卡片内容 渐变色 Icon + 分类名称 + 一句话描述 + Top3 效果器名称
交互 点击 → 对应排行榜面板从右侧滑入（300ms ease-out）
数据来源 V1：手动维护的 pedalData JSON 对象；V2：后端数据库
Top3 展示逻辑 该类目下最具代表性的三款效果器，手动选取，仅展示不可点击

7.2 排行榜面板

属性 规格
打开动画 `translateX(105%)` → `translateX(0)`, 300ms cubic-bezier(0, 0, 0.2, 1)
关闭方式 点击返回箭头 / 左滑手势（V2）
渲染策略 延迟渲染 — 首次打开时生成 DOM，关闭后缓存不复用（`panel._rendered` 标记）
排序 按 `hot` 字段降序。hot 值 V1 手动设定（0-100 整数）
V2 排序算法 `hot = 帖子数×0.4 + 收藏数×0.3 + 浏览量×0.2 + 近7天互动×0.1`
排序切换 V2 添加 SegmentedControl：「按热度」「按时间」
HOT 标记 当 `hot >= 90` 时显示红色 HOT 徽章；阈值为可配置参数
序号样式 1 金 / 2 银 / 3 铜（渐变色圆形）；4+ 灰色圆形
效果器行内容 序号 + 效果器名称 + 品牌名 + 标签（最多 3 个）+ 箭头
空数据 显示「暂无数据」（不应出现，但需要兜底）

7.3 效果器详情弹窗

属性 规格
类型 Bottom Sheet（底部弹出面板）
最大高度 屏幕高度的 65%
打开动画 半透明遮罩淡入 + Sheet 从底部滑入（300ms）
关闭方式 X 按钮 / 点击遮罩 / 向下拖拽（V2）/ Escape 键
内容结构 手柄 → 效果器名称+品牌 → 简介 → 分隔 →「相关帖子」→ 帖子列表
相关帖子 仅展示该效果器的帖子（同一 `pedal.posts[]` 数组），不跨效果器推荐
帖子不足 若 posts 少于 3 篇，剩余空间留空；不填充无关内容
零帖子 显示「暂无相关帖子，成为第一个讨论的人」
简介缺失 隐藏简介区块（非必填字段）
品牌为空 隐藏品牌行

7.4 发布帖子流程

状态 界面表现 用户可操作
**编辑态** 标题 + 正文输入框 + 关联效果器选择器 + 发布按钮（蓝色） 自由编辑
**校验失败** 红色文字「请填写内容」出现在空字段下方 修改后重试
**提交中** 按钮变为 Loading 动画 + 灰色 + 文字「发布中...」 不可操作
**成功** 绿色对勾动画 + 「发布成功」→ 自动跳转首页 无需操作
**失败** 「网络开小差了，请重试」+ 重试按钮 点击重试 / 退出

Tab 图标（Lucide SVG） 目标页面 特殊说明

8. 数据模型（MVP）

8.1 效果器（Pedal）


{
  id: string            // 唯一标识，如 "boss-ds-1"
  name: string          // 产品全称，如 "Boss DS-1 Distortion"
  brand: string         // 品牌名
  category: enum        // distortion | overdrive | delay | reverb | modulation | multi
  tags: string[]        // 标签，如 ["经典", "入门首选"]
  hot: number           // 热度值 0-100，V1 手动设定
  intro: string         // 简介段落（200 字以内）
  imageUrl?: string     // 产品图（V2）
  releaseYear?: number  // 发布年份（V2）
}

8.2 帖子（Post）


{
  id: string
  title: string
  content: string
  author: { id, name, avatar? }
  pedalId?: string      // 关联的效果器（可选）
  likes: number
  comments: number
  createdAt: timestamp
}

9. 社区治理规则

9.1 社区规则（V1）

1. 禁止盗版 — 不得发布、销售或宣传盗版/山寨/商标侵权效果器。允许合理讨论复刻电路（Clone），但须明确标注非原厂产品。

2. 禁止人身攻击 — 不得针对用户进行侮辱、威胁或骚扰。允许真实体验分享，即使是负面的，但不允许恶意品牌攻击（重复刷差评、无事实依据的抹黑）。

3. 禁止垃圾信息 — 禁止与效果器无关的广告、刷屏、引流外链。

4. 商家信息披露 — 商家身份用户须在个人简介或帖子中标注商业利益关系。

9.2 治理原则

  • 区分「攻击人/品牌」与「评价产品」—— 差评不等于违规，刷差评等于违规
  • 内容审核优先人工 + 社区举报，避免自动化误伤
  • 首次违规警告，重复违规封禁

10. 冷启动策略

10.1 内容冷启动

策略 具体做法 阶段
**运营自产** 官方账号发布效果器介绍帖、对比评测、教程 上线前→上线初期
**搬运翻译** 搬运外网高质量评测内容并翻译（标注原作者和出处；版权归原作者，侵权即删） 上线初期
**邀请种子用户** 邀请 5-10 位效果器圈活跃用户（群主/B站UP主）入驻并承诺内容推荐曝光 上线前
**效果器数据库预填充** 手动录入 60+ 款热门效果器的基本信息 上线前

10.2 用户冷启动

策略 具体做法
**微信群引流** 在现有效果器交流群发布内容链接，将讨论从群聊引导至平台
**SEO/长尾搜索** 每篇帖子标题包含效果器型号+关键词，利于搜索引擎收录
**邀请奖励** 邀请 3 位好友注册 → 获得「早期用户」标识（V1.1）

10.3 转型时机判断

从「搬运驱动」到「UGC 驱动」的转型信号：

  • UGC 帖子占比超过总帖子的 30%
  • 单日自发帖子数（非运营发布）超过 10 条
  • 出现用户自发撰写的效果器对比评测（非邀请内容）

每周活跃内容贡献者数（WAU Contributors） — 每周至少发布 1 篇帖子或 3 条评论的用户数

指标 MVP 目标（上线后 3 个月） 测量方式

12. 设计系统

12.1 设计规范

  • 设计风格：Glassmorphism（毛玻璃） + 蓝白主色调
  • 设计 Token 体系：3 层架构（Primitive → Semantic → Component），所有颜色/间距/阴影/圆角/动效均 Token 化
  • 响应式：Mobile-first，主视口 390×844px（iPhone 14 尺寸），最大宽度 390px + 居中
  • 动效：100ms-300ms 范围，cubic-bezier 缓动，需兼容 prefers-reduced-motion
  • 无障碍：所有交互元素必须有 focus 可见状态 + 最小 24×24px 触控区域

13. 技术约束与决策

13.1 已知约束

  • 当前无后端开发能力 → MVP 以交互式原型形式交付，用作开发沟通材料
  • 无数据库维护能力 → 数据以 JSON 对象硬编码于前端
  • 无用户系统 → 登录/注册/权限管理标记为 V1.1

13.2 技术选型建议（供开发团队讨论）

  • 前端框架：React 19 + TypeScript + Tailwind v4（项目已有 React-Tailwind 适配器）
  • 后端：Node.js / Go，RESTful API
  • 数据库：PostgreSQL（用户/帖子/效果器数据）+ Meilisearch（全文搜索）
  • 图片存储：阿里云 OSS / AWS S3
  • 部署：Vercel（前端）+ 阿里云/腾讯云（后端）

14. 风险与开放问题

风险 严重度 缓解措施
**冷启动内容不足** 高 运营自产 + 搬运翻译过渡 + 种子用户邀请
**版权纠纷（翻译内容）** 中 标注出处、作者可联系下架、逐步转向 UGC
**社区水化（商家广告泛滥）** 中 商家认证 + 商业内容标识 + 社区规则
**竞品出现** 低 垂直深度是壁垒 — 效果器数据的完整性和社区氛围难以复制
**用户增长缓慢** 中 不追求爆发式增长，优先做深内容质量和社区氛围

14.1 开放待决策问题

1. KOL 认证的具体数值阈值（赞数/收藏数/关注数）？

2. 帖子排序是否需要「热门」算法 vs 纯时间序？

3. 二手交易是平台内完成还是仅引流至闲鱼/淘宝？

4. 效果器数据库的字段范围（参数规格/试听音频/视频种草）？
